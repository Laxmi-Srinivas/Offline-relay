PROTECTION LIMITS

Encryption does not establish peer identity

The Android Security code uses ephemeral X25519, directional HKDF-SHA256 keys and AES-256-GCM encrypted chat/control packets with counters. The key exchange is unauthenticated, so active key substitution remains possible. Names are self-asserted. Bluetooth link encryption/authentication and exhaustive storage/backup behavior remain unverified.

Logs, notification previews, screenshots, recipients and device backups have separate exposure paths. A local report feature is not server moderation.

Current assumptions and findings

Both nearby users need the Onya Android test build installed beforehand. This page presents Android evidence only; the browser simulation is illustrative and makes no Bluetooth connection.
